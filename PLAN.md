# План: клиент для vpn-core на Rust

Цель — графический клиент для [vpn-core](https://github.com/ERGFT/vpn-core),
**полностью на Rust** там, где это возможно: общая логика, интерфейс
(Slint), платформенные адаптеры. Допустимы только тонкие вспомогательные
слои там, где платформа не оставляет выбора (например, класс `VpnService`
на Android обязан быть на Kotlin/Java).

Приоритет платформ: **Windows → Android → Linux**. Apple (macOS, iOS,
tvOS) отложены: у них отдельная модель сетевых расширений.

Статус этапов (обновляется по ходу работы):

| Этап | Что | Статус |
|---|---|---|
| 0 | Каркас Rust-клиента: профили, запуск ядра через C ABI, журнал, сборки под три платформы | ✅ есть, предварительно |
| 1 | Новый интерфейс: единая тема, адаптивный макет, экран с кнопкой питания | ✅ готово (скриншоты desktop/mobile, обе темы) |

## Принципы

- **Правда о статусе.** «Проверено» значит: запущено и результат записан в
  [docs/STATUS.md](docs/STATUS.md). Остальное — «не проверено».
- **Секреты не в журнал, не в аргументы процесса.** VLESS-ссылка живёт в
  защищённом хранилище ОС.
- **Ошибка вместо молчания.** Неподдерживаемая настройка — отказ с
  понятным текстом, а не тихая подмена.
- **Один интерфейс.** Платформенные различия — в адаптерах, а не в копиях
  экранов.
- **Бинарники не в git.** `wintun.dll`, готовые сборки, архив ядра
  скачиваются или собираются скриптом с проверкой SHA-256 (этап 4).

## Зависимости

- Этап 3 зависит от вас: в аккаунте GitHub ошибка платежей/лимита
  расходов (задания Actions не стартуют вообще).
- Этап 6 требует тестового сервера VLESS/REALITY и реальных
  устройств; без них заявлять «работает» нельзя.
- Лицензия: ядро GPL-3.0-or-later, значит клиент тоже. Репозиторий
  приватный — до публикации релизов нужно решить вопрос исходников.
