# Reality Client for Windows

Функциональный Windows GUI для `reality-core`; сборка предназначена для Windows 10/11 x64. Главный артефакт — `dist/RealityClient.exe`: Windows Forms-интерфейс и ядро находятся в одном EXE; при первом запуске ядро извлекается в закрытую пользовательскую папку `%LOCALAPPDATA%\RealityClient`.

## Что умеет текущая сборка

- сохранять несколько VLESS-профилей в хранилище Windows DPAPI, доступном этому пользователю;
- проверять конфигурацию штатной командой ядра `--check` до включения прокси;
- запускать настоящее ядро в режиме mixed SOCKS5/HTTP на `127.0.0.1:1080`;
- временно включать системный прокси Windows через штатный `--system-proxy` ядра;
- останавливать ядро штатным Ctrl+C и возвращать исходные пользовательские настройки прокси;
- сохранять резервную копию затрагиваемых настроек и предлагать восстановление после аварийного завершения GUI;
- не помещать VLESS-ссылку в аргументы процесса, системный журнал или GUI-журнал;
- редактировать, импортировать и экспортировать полные конфигурации sing-box/Xray в отдельной студии;
- проверять эти конфигурации встроенным ядром до запуска и запускать их без пересборки GUI;
- передавать ядру все поддержанные им входы/выходы, группы и подписки, маршрутизацию, DNS, TUN, API, транспортные и протокольные параметры через полный JSON-конфиг.

Кнопка **«Настройки…»** открывает студию полного конфига. Она работает с исходной JSON-конфигурацией напрямую, поэтому новые и редкие поля ядра доступны без изменения интерфейса. Набор возможностей определяется текущей версией ядра; неподдерживаемые поля ядро отклоняет своей проверкой. Рядом с конфигом должны лежать все связанные файлы (`link_file`, сертификаты, rule sets и др.). Текст JSON сохраняется открытым; для секретов используйте отдельные файлы с ограниченными правами. Перед включением полного конфига отключите режим профиля, а системный прокси включайте только если он нужен для вашего конфига.

Обычный режим профиля — рабочий **Windows proxy-клиент**, а не полнотрафиковый TUN VPN. Некоторые программы игнорируют системный прокси и продолжат соединяться напрямую. Студия позволяет передать ядру конфигурацию с TUN, но сама не устанавливает/не управляет Wintun, службой или правами администратора и не проверяет успешный системный захват трафика. Android VpnService и Linux GUI не реализованы.

В режиме профиля подключение считается поднятым, когда ядро прошло `--check`, открыло локальный порт и ответило на SOCKS5 greeting. В режиме полного конфига GUI проверяет конфиг и подтверждает, что процесс ядра остаётся запущенным; конкретные listener/TUN и подключение к удалённому серверу нужно проверять по самим настройкам и реальным запросом. Ни одна из этих локальных проверок сама по себе не доказывает доступность удалённого REALITY-сервера.

## Запуск

Откройте `dist/RealityClient.exe`, добавьте профиль, вставьте ссылку `vless://…` и нажмите «Подключить». Во время работы часть приложений пойдёт через системный прокси. Не все приложения используют его.

Профили зашифрованы DPAPI для текущей учётной записи Windows. Временный `server.txt` с открытой ссылкой создаётся только на время работы ядра в `%LOCALAPPDATA%\RealityClient`; при обычном отключении он перезаписывается нулями и удаляется. Если процесс или питание завершатся аварийно, файл может остаться до следующего старта GUI, который удаляет его перед работой. Не копируйте пользовательскую папку приложения в общедоступное место.

Если GUI аварийно закрыли и прокси остался включён, запустите приложение и используйте «Восстановить прокси». Клиент сохранит прежние `ProxyEnable`, `ProxyServer` и `ProxyOverride`; автоматическое восстановление меняет их только когда активный сервер всё ещё указывает на `127.0.0.1:1080`.

## Проверка

Сборка включает детерминированную интеграционную проверку, которая временно включает системный прокси на loopback, проверяет JSON через ядро, поднимает listener, проверяет SOCKS5 greeting, проверяет код штатного выхода ядра и восстанавливает настройки Windows:

```powershell
.\dist\RealityClient.exe --self-test
```

Проверка использует тестовый профиль на `127.0.0.1:1`, не настоящий сервер.

Результат сохраняется в `%LOCALAPPDATA%\RealityClient\self-test.log`; код завершения 0 означает, что локальные проверки прошли. Тест восстанавливает настройки в `finally`, но перед ним закройте браузеры или приложения, чтобы они не сделали запрос через кратковременно включённый тестовый прокси.

Проверить, что окно и основные доступные элементы интерфейса отображаются, можно скриптом `tests/window_smoke.ps1`.

## Исходники и сборка

- `src/` — исходники GUI и управления ядром;
- `third_party/reality-client.exe` — ядро, встроенное ресурсом в итоговый EXE;
- `third_party/vpn-core-source.zip` — исходный код ядра на commit `ee68039943ebb2aaf3287bf622ae34c18bfa0cae`;
- `third_party/vpn-core-source.commit` — точная ревизия исходников ядра;
- `build.ps1` — сборка GUI на штатном компиляторе .NET Framework;
- `build_core.ps1` — пересборка актуального ядра из исходников MinGW/MSYS2 + Rust, затем пересборка GUI.

Собрать GUI-оболочку можно без Flutter и Visual Studio:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\build.ps1
```

Для пересборки ядра установите Rustup, Git и MSYS2 в пользовательский каталог, затем в MSYS2 запустите `pacman -S --needed mingw-w64-x86_64-gcc mingw-w64-x86_64-cmake mingw-w64-x86_64-nasm`. Добавьте GNU-host toolchain Rust:

```powershell
rustup toolchain install stable-x86_64-pc-windows-gnu --profile minimal
```

Когда эти зависимости установлены, пересоберите ядро и GUI. Скрипт проверит SHA-256 закреплённого архива, распакует его во временную папку, выполнит сборку и удалит распакованные исходники:

```powershell
.\build_core.ps1
```

Требуется Windows с .NET Framework 4.5+ (есть в поддерживаемых Windows 10/11) и `csc.exe`. `build.ps1` собирает GUI и встраивает бинарник ядра из `third_party/reality-client.exe`. Текущий исходник ядра лицензирован GPL-3.0-or-later; условия распространения GUI и вложенного ядра описаны в `THIRD_PARTY.md`.
