# Выпуск версии

Релиз собирает и публикует CI: достаточно поставить тег.

Содержание:

1. [Как выпустить](#1-как-выпустить)
2. [Что делает CI](#2-что-делает-ci)
3. [Чего ещё нет](#3-чего-ещё-нет)

## 1. Как выпустить

1. Напишите заметки `docs/releases/<тег>.md` (русский и английский; что проверено и что нет — честно, по [STATUS.md](STATUS.md)). Без файла релиз получит автоматические заметки.
2. Убедитесь, что `main` зелёный и заметки уже в `main`.
3. Поставьте тег на нужный коммит `main` и отправьте его:

```sh
git tag -a v0.1.0-preview.1 -m "Reality Client v0.1.0-preview.1"
git push origin v0.1.0-preview.1
```

Тег с дефисом (`v0.1.0-preview.1`) становится пре-релизом, без дефиса (`v0.1.0`) — обычным.

## 2. Что делает CI

Тег `v*` запускает три workflow (Linux, Windows, Android). Каждый собирает свой пакет, считает SHA-256 и отдельным заданием публикует файлы в релиз через `.github/scripts/publish-release.sh`: первый из трёх создаёт релиз (с заметками из `docs/releases/<тег>.md`), остальные добавляют свои файлы. Файлы релиза:

| Файл | Платформа |
|---|---|
| `RealityClient-Rust-windows-x64.zip`, `SHA256SUMS-windows-x64.txt` | Windows x64 |
| `RealityClient-Rust-android-arm64-debug.apk`, `SHA256SUMS-android-arm64.txt` | Android arm64 |
| `RealityClient-Rust-linux-x86_64.tar.gz`, `SHA256SUMS-linux-x86_64.txt` | Linux x86_64 |

Windows-сборка идёт около получаса.

## 3. Чего ещё нет

- Подписи: Windows-сборка не подписана (SmartScreen предупреждает), APK подписан отладочным ключом. Подпись требует сертификата и ключа владельца; они не хранятся в репозитории.
- Инструкции обновления между версиями (пока — «удалите и поставьте новую»).
