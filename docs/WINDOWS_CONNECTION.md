# Подключение Windows / Windows connections

## Как применяется выбранный сервер

В обычном режиме клиент запускает mixed-прокси на `127.0.0.1:1080` с выбранной
VLESS-ссылкой. При включённом системном прокси Windows браузеры, использующие
настройки системы, направляют запросы на этот порт. Приложения с собственным
прокси и UDP/QUIC-трафик могут использовать другой путь.

В полном конфиге запускается **текущий текст редактора**, включая применённые
переключателями изменения. Сохранение файла отдельно не требуется для запуска.
Переключатель **Использовать выбранный сервер** связывает VLESS-профиль с выходом
`proxy` в sing-box JSON, сохраняя правила, DNS и TUN. Для самостоятельного JSON,
особенно Xray или конфигурации с несколькими выходами, отключите эту привязку.
Если нужного VLESS-выхода `proxy` нет, клиент выдаёт ошибку вместо скрытой подмены
другого выхода. Исходный файл JSON не перезаписывается подключением.

Полный конфиг **без TUN** сам по себе не перенаправляет браузер. В этом режиме
системный прокси не включается автоматически; нужен настроенный вручную путь
к входящему прокси. Windows TUN требует прав администратора и комплектной
`wintun.dll`. Применение маршрутов проверяется отдельно от запуска ядра. Подробнее о вводе ссылок: [подписки и серверы](SUBSCRIPTIONS.md).

## Что означает состояние подключения

«Ядро запущено» означает успешный запуск, а не проверку всей сети. На главной
странице показаны сервер и режим **запущенной сессии**, а не профиль, который
пользователь выбрал после подключения. Проверка внешнего IP отправляет запрос
через локальный прокси; правила JSON могут направить домен проверки напрямую.

Клиент проверяет состояние системного прокси после включения и во время работы.
Если другой клиент переключил или отключил его, появляется предупреждение.
Клиент не перехватывает настройки обратно автоматически. Незавершённая копия
восстановления также не удаляется автоматически; чужой прокси не восстанавливается
поверх работающего приложения.

## Проверено и не проверено

- Изолированный настоящий core: HTTP CONNECT и SOCKS-запросы доходят до двух
  разных локальных VLESS-серверов при смене сохранённого профиля. Старый файл
  JSON на диске при этом отличается от редактора и остаётся неизменным.
- Однократная проверка сохранённого локального профиля: HTTPS-запрос через
  отдельный прокси завершился, выход отличался от обычного маршрута Windows.
  Личные ссылки и адреса не записывались в отчёт.
- Нативный маршрут браузера и Windows TUN не проверялись на основном ПК:
  работающий Happ и системные сетевые настройки сохранены.

## English summary

Profile mode uses the selected VLESS server through a mixed local proxy. Full
configuration startup now uses the current editor snapshot. Explicit selected
server binding targets the sing-box VLESS outlet tagged `proxy` and preserves
TUN/DNS/routes; disable it for independent raw JSON configurations. Runtime
files are separate from saved editor files. A full configuration without TUN
does not automatically route the browser. UI reports the active session and
warns about foreign Windows proxy changes without taking ownership back.
Local VLESS HTTP CONNECT/SOCKS forwarding and one explicitly selected local
profile's HTTPS request passed; native browser routing and Windows TUN remain
unverified. Happ and host network settings were not changed.
